# apicompat

Convert LLM API payloads between **OpenAI Chat Completions**, **OpenAI
Responses** and **Anthropic Messages** — requests, responses and SSE streams,
in all 12 directions.

```bash
pip install apicompat        # or: uv add apicompat
```

No runtime dependencies beyond the Python standard library. Python 3.11+.

## Why

Every provider speaks a slightly different dialect. `apicompat` translates
between them through a shared intermediate representation, so all six request
directions and all six response directions behave consistently — including the
details that break naive converters: thinking blocks and signatures, tool
call/result pairing, cache token accounting, refusals, and stream termination.

Wire behaviour is not invented here: it is pinned to [sub2api]'s Go
`apicompat` package by a 163-case golden parity suite generated by running
sub2api's own converters.

[sub2api]: https://github.com/Wei-Shaw/sub2api

## Quick start

### Convert a request

```python
from apicompat import convert_request

# The client speaks Anthropic; the upstream expects OpenAI Responses.
upstream_body = convert_request(
    "anthropic_messages",      # source
    "openai_responses",        # target
    client_body,
)
```

### Convert a non-streaming response

```python
from apicompat import convert_response

client_body = convert_response(
    "openai_responses",        # what the upstream returned
    "anthropic_messages",      # what the client expects
    upstream_body,
)
```

### Convert a stream

```python
from apicompat import convert_stream

for chunk in convert_stream(
    "openai_responses",        # what the upstream streams
    "anthropic_messages",      # what the client expects
    upstream_chunks,           # any Iterable[bytes]
):
    response.write(chunk)
```

`convert_stream` accepts chunks split at *any* byte offset — upstream framing
never has to align with SSE event boundaries. When the upstream ends without a
termination event, the closing sequence is synthesized so the client's parser
finishes cleanly. Output is emitted in small pieces (`chunk_size`, default 64
bytes) so streaming starts immediately instead of waiting for a whole upstream
chunk.

### Async

```python
from apicompat import astream

async for chunk in astream("openai_responses", "anthropic_messages", upstream):
    await response.write(chunk)
```

Conversion is pure CPU work, so `astream` runs inline on the event loop and
only awaits the upstream read. `convert_stream` and `astream` share one
implementation (`StreamCodec`), so their output is byte-identical.

## API

| Function | Purpose |
|---|---|
| `convert_request(source, target, payload, *, stream=False, options=None)` | Request body, `dict` → `dict` |
| `convert_response(source, target, payload, *, options=None)` | Non-streaming response, `dict` → `dict` |
| `convert_stream(source, target, chunks, *, chunk_size=64)` | SSE stream, `Iterable[bytes]` → `Iterator[bytes]` |
| `astream(source, target, chunks, *, chunk_size=64)` | SSE stream, `AsyncIterable[bytes]` → `AsyncIterator[bytes]` |
| `StreamCodec(source, target, *, chunk_size=64)` | Manual control: `.feed(chunk)` / `.finalize()` |
| `encode_stream_terminator(protocol)` | Just the stream's closing event |

Protocol names are `"openai_chat"`, `"openai_responses"` and
`"anthropic_messages"`. The `Protocol` enum is accepted anywhere a name is.

### When to use `StreamCodec`

`convert_stream` covers the common case. Reach for `StreamCodec` when the
caller controls the stream's lifecycle — for example, writing a terminator
after an upstream connection drops:

```python
from apicompat import StreamCodec, encode_stream_terminator

codec = StreamCodec("openai_responses", "anthropic_messages")
try:
    async for chunk in upstream:
        for out in codec.feed(chunk):
            yield out
    for out in codec.finalize():
        yield out
except UpstreamDropped:
    yield encode_stream_terminator("anthropic_messages")
```

`finalize()` is idempotent and safe to call after an early exit.

### Response model name

Providers echo the upstream model id in the response. When the client asked
for a friendly alias, pass it so the converted response carries that instead:

```python
convert_response("openai_responses", "anthropic_messages", body,
                 options={"model": "my-alias"})
```

## Error handling

Conversion failures raise `ConversionError`, or one of its subclasses:
`ValidationError` (the payload is malformed) and `CapabilityNotSupportedError`
(the target protocol cannot express something the source carries).

Malformed *stream* events are skipped rather than aborting the stream — a
proxy should degrade, not fail, on one bad frame.

An unknown protocol name raises `ConversionError` immediately.

## Compatibility

The golden parity suite lives in `tests/parity`: 163 fixtures generated by
running sub2api's converters, replayed here and compared field by field
(nondeterministic ids and timestamps masked). It is the spec — if a future
change alters wire shape, that suite fails.

```bash
uv run --package apicompat pytest packages/apicompat/tests
uv run python packages/apicompat/examples/demo.py
```

`examples/demo.py` runs offline: request conversion, response conversion,
stream conversion, the async variant and the dropped-upstream terminator.
